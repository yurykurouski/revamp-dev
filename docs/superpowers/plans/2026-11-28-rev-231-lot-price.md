# REV-231 (E3.1): Deterministic lot price from the audit — Implementation Plan

> **For agentic workers:** executed by the `implementer` agent (Sonnet), whole plan in one run, TDD. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A pure function turns a completed audit into a lot price (integer cents plus a per-signal breakdown) and a coarse audit band, with platform settings validated by Zod.

**Architecture:** One new module `packages/validation/src/lot-price.ts`, re-exported from `@revamp/validation`. It reads four deterministic audit signals, maps each to a "need" in [0, 1], averages the measured ones by weight (renormalized), and interpolates between a floor and a cap. Settings come from env through `lotPriceSettingsFromEnv`, which the API env loads at startup so a bad value fails fast. Nothing consumes the price yet; E3.2 (REV-232) creates lots with it.

**Tech Stack:** TypeScript, Zod, Vitest.

**Spec:** Linear REV-231 (acceptance criteria), REV-171 (E3) decisions comment of 2026-11-28, Business Analysis US5 ("cost floor plus weighted audit signals (site-era score, accessibility violations, missing web standards, slow LCP), never by an LLM; a signal that could not be measured is left out and the weights are renormalized").

## Global Constraints

- Root `AGENTS.md` §3.2.2: no LLM, no randomness, no clock, no stand-in value for a failed measurement.
- §3.2.4: settings validated with Zod from `@revamp/validation`.
- §3.2.5: Vitest for every branch; `.spec.ts` only (`.spec.tsx` is skipped).
- Amounts are integers in minor units (cents). Currency is an ISO 4217 code, upper case, 3 letters.
- No new dependencies.

## Decisions (made here, not left to the implementer)

| Signal key | Source field | Need in [0, 1] | Absent when | Default weight |
|---|---|---|---|---|
| `siteEra` | `audit.siteEra.score` | `min(score / 6, 1)` (6 = twice `SITE_DATED_THRESHOLD`) | `siteEra` absent | 35 |
| `accessibility` | `audit.a11ySummary.violationsCount` | `min(count / 20, 1)` | `a11ySummary` absent | 25 |
| `standards` | `audit.scores.standards` | `(100 - standards) / 100`, clamped to [0, 1] | `scores.standards` absent | 20 |
| `lcp` | `audit.webVitals.lcp` (ms) | `clamp((lcp - 2500) / (6000 - 2500), 0, 1)` | `webVitals.lcp` absent | 20 |

- Weighted need `need = Σ(wᵢ·needᵢ) / Σwᵢ` over measured signals with `wᵢ > 0`. A signal with weight 0 counts as left out.
- `amount = floor + Math.round((cap - floor) * need)`. No measured signal → `need = null`, `amount = floor`. The result is always within [floor, cap].
- Defaults: `floorCents 1500`, `capCents 9900`, `currency 'EUR'`, weights as above.
- Band from `need`: `A` ≥ 0.75, `B` ≥ 0.5, `C` ≥ 0.25, otherwise `D`; `null` need → no band (`undefined`). **A means the strongest case for a redesign** (the most valuable lot). Cut points are constants, not settings.
- Env names: `LOT_PRICE_FLOOR_CENTS`, `LOT_PRICE_CAP_CENTS`, `LOT_CURRENCY`, `LOT_PRICE_WEIGHT_SITE_ERA`, `LOT_PRICE_WEIGHT_ACCESSIBILITY`, `LOT_PRICE_WEIGHT_STANDARDS`, `LOT_PRICE_WEIGHT_LCP`. An empty string counts as unset.

## Review Focus

1. **A signal present with value 0** (`violationsCount: 0`, `siteEra.score: 0`, `scores.standards: 100`) is measured, not missing: it lowers the price. Test `treats a zero measurement as measured`.
2. **An LCP below 2500 or a standards score above 100 / below 0** clamps to need 0 / [0, 1]; the price never leaves [floor, cap]. Test `clamps out-of-range values`.
3. **All weights 0** or **cap < floor** in env must fail at startup, not produce NaN. Tests in `lotPriceSettingsFromEnv`.
4. **Key order / extra fields** in the audit object must not change the price (determinism across a Mongoose doc and a plain object). Test `ignores fields it does not read` (same price for an audit with extra fields like `designCritique`, `screenshotUrls`).
5. **Lowercase currency** (`eur`) is upper-cased, not rejected; `EURO` is rejected.

**Interfaces (Produces, used by REV-232 and REV-239):**

```ts
export const LOT_PRICE_SIGNALS = ['siteEra', 'accessibility', 'standards', 'lcp'] as const;
export type LotPriceSignal = (typeof LOT_PRICE_SIGNALS)[number];
export const LOT_BANDS = ['A', 'B', 'C', 'D'] as const;
export type LotBand = (typeof LOT_BANDS)[number];
export const LotBandSchema: z.ZodEnum<...>;            // z.enum(LOT_BANDS), for listing filters later

export const LotPriceSettingsSchema: z.ZodType<LotPriceSettings>; // strict object, refines below
export interface LotPriceSettings {
  floorCents: number;      // int ≥ 0
  capCents: number;        // int ≥ floorCents (refine, message 'capCents must be at least floorCents')
  currency: string;        // /^[A-Z]{3}$/ after toUpperCase
  weights: Record<LotPriceSignal, number>; // each ≥ 0, finite; sum > 0 (refine, message 'at least one weight must be positive')
}
export const DEFAULT_LOT_PRICE_SETTINGS: LotPriceSettings;

/** The audit fields the price reads; a Mongoose lean doc or an IAudit fits */
export type PriceableAudit = Pick<IAudit, 'siteEra' | 'a11ySummary' | 'webVitals'> & { scores?: Pick<IAuditScores, 'standards'> };

export interface LotPriceSignalPart { signal: LotPriceSignal; value: number; need: number; weight: number }
export interface LotPrice {
  amountCents: number;
  currency: string;
  /** Weighted need in [0, 1]; null when no signal was measured */
  need: number | null;
  /** Measured signals only, in LOT_PRICE_SIGNALS order; `weight` is the renormalized share (sums to 1) */
  signals: LotPriceSignalPart[];
  /** Signals left out because they were not measured or weigh 0 */
  missing: LotPriceSignal[];
}

export function priceFromAudit(audit: PriceableAudit, settings?: LotPriceSettings): LotPrice; // default DEFAULT_LOT_PRICE_SETTINGS
export function lotBandFromNeed(need: number | null): LotBand | undefined;
export function auditBand(audit: PriceableAudit, settings?: LotPriceSettings): LotBand | undefined; // lotBandFromNeed(priceFromAudit(...).need)
export function lotPriceSettingsFromEnv(env: Record<string, string | undefined>): LotPriceSettings; // throws ZodError on bad values
```
